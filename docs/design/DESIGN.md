# SongStub · 曲票 — 视觉与交互设计说明

> 产品名：**SongStub**（中文名「曲票」）
> 代码库：`songup-queue`（沿用原仓库名，避免断链）
> 血缘：派生自 [`motz0815/songup`](https://github.com/motz0815/songup)，MIT
> 版本：v2.1.0

---

## 1. 为什么叫「曲票」

这个产品只有两个动作：**客人递一张票**，**主机撕一张票**。

原版叫 SongUp，名字描述的是「把歌顶上去」；但代码里真正被反复修正的东西是**票**——
每人几张、谁先谁后、撕掉的票什么时候能再递。公平去重、配额占位、冷却表，
全是票据规则。所以新名字直接长在机制上：

- **SongStub** = song + ticket stub（票根）
- **曲票** = 曲子的票

它同时解释了界面的形状：队列不是列表，是一叠票根。

---

## 2. 两个面，两种光

聚会现场有两种人，站在两种光里。设计不做「一套皮肤两处套用」，而是承认这件事：

| | 主机页 `/host` | 客人页 `/` |
|---|---|---|
| 场景 | 投在墙上 / 电视上，房间是暗的 | 拿在手里，房间是亮的 |
| 底色 | 墨黑（`#14100D`）——「舞台」 | 纸白（`#FBF5E9`）——「你手里的票」 |
| 主体 | 一张撕下来的大票根 + 一叠待撕的票 | 曲库列表 + 你的票夹 |
| 强调色 | 黄铜（`#E0A33F`） | 黄铜 + 墨（同源） |
| 字号 | 远看：标题 28–44px | 近看：正文 15–16px |

**黄铜是两者之间唯一的硬连接。** 舞台的灯光和票根上的印泥是同一个颜色。

## 4. 字体

零外链，全部系统字体（页面必须能从 `file://` 与离线局域网打开）。

| 角色 | 字体栈 | 用在哪 |
|---|---|---|
| 展示 Display | `Georgia, "Times New Roman", "Songti SC", "Noto Serif SC", serif` | 页名、票面标题、票号 |
| 界面 UI | `-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` | 正文、按钮、表单 |
| 数字 Mono | `ui-monospace, "Cascadia Mono", Menlo, monospace` | 票号、序号、计时 |

字号阶：`11 / 12 / 13 / 15 / 17 / 21 / 28 / 36`，行高 1.45–1.6。
数字一律 `font-variant-numeric: tabular-nums`——队列序号跳动时不能左右抖。

## 5. 图形语言：票根

一个组件撑起整个界面。

```
 ┌──────────────┬─────────┐
◖  01  晴天      ┊  guest  ◗     ← 左缺口 + 虚线撕口 + 右缺口
 │     by 阿宝   ┊  ·4:21  │
 └──────────────┴─────────┘
```

实现要点（都在 `templates/*.html` 里，无构建步骤）：

- **缺口**：`::before` / `::after` 两个圆形，颜色取父容器底色（`--notch`），
  所以票根放在暗底就是暗缺口，放在纸底就是纸缺口——不写死。
- **撕口**：`border-left: 1px dashed`，颜色 `--paper-300` 压暗一档。
- **当前票**（主机页）：`transform: rotate(-1.2deg)` + 轻微投影，
  像刚从票本上撕下来随手放在桌上。
- **待播票**（队列）：不旋转，按序号轻微右移 0.6px 递增，形成「一叠」的错觉。
- **动画**：递票时票根从下方 8px 处升起 + 淡入（220ms）。
  `prefers-reduced-motion: reduce` 下全部取消位移，只保留透明度。

---

## 6. 图标

原创 SVG，几何构造，`stroke-linecap: round`，2px 线宽（24 网格）。

- **主标**：一张票 + 一个播放三角。票的左右缺口在 16px 会糊，所以小尺寸下只保留
  播放三角与两条票线。
- **功能图标**：`play` `skip` `mute` `trash` `search` `qr` `plus` `check`。
  全部内联在 HTML 里（`<svg>` 直接写），不走图标字体、不请求外部文件。

## 7. 交互升级清单

| # | 位置 | 之前 | 现在 | 为什么 |
|---|---|---|---|---|
| 1 | 主机页 | 只有 URL 文字 | **扫码入场**：二维码 + 大号地址 + 一键复制 | 投屏场景里没人会手打 IP |
| 2 | 主机页 | 队列是纯文字列表 | 票根列表 + 序号 + 点歌人 + 单条删除 | 一眼看出「还剩几张票」 |
| 3 | 主机页 | 进度只靠画面 | 本地曲目显示**进度条 + 剩余时间** | 投屏离得远，进度条比秒数可读 |
| 4 | 主机页 | 无键盘说明 | 空格 / → 下一首，`M` 静音，`?` 快捷键卡 | 主机手在键盘上，不在鼠标上 |
| 5 | 主机页 | 加载态无 | 骨架屏 + 空态插画文案 | 消除「是不是卡了」 |
| 6 | 客人页 | 配额只有一行小字 | **票夹**：两个打孔位，用掉一个就空一个 | 配额是这个产品最容易踩的规则 |
| 7 | 客人页 | 加入后只有 toast | 票根飞入票夹 + 队列位置即时更新 | 让「我排第几」在 0.3 秒内可见 |
| 8 | 客人页 | 无排队预估 | 「还要等 N 首」 | 减少重复点歌的冲动 |
| 9 | 双端 | `#msg` 无朗读 | `role="status" aria-live="polite"` | 屏幕阅读器 |
| 10 | 双端 | 无焦点样式 | 2px 黄铜 focus ring，`:focus-visible` | 键盘可达 |
| 11 | 双端 | 无 `prefers-reduced-motion` | 全部动画可关 | 前庭敏感 |
| 12 | 双端 | favicon 404 | 内联 SVG favicon | 控制台干净 |

**不做的事**（避免过度工程）：不改队列引擎语义、不加账号、不加多房间、
不引入前端框架或构建链、不加任何需要联网的字体或图标。

## 8. 布局

**主机页**（≥980px）：`1fr 360px` 两栏。左栏舞台 16:9 + 当前票 + 控制条；
右栏票叠 + 统计 + 扫码卡。980px 以下单栏，扫码卡移到顶部。

**客人页**：单栏，最大宽 480px 居中。顺序＝使用顺序：
票夹 → 搜索 → 正在播放 → 队列。

---

## 9. 验收口径

1. **适配**：320 / 390 / 768 / 1024 / 1366 / 1920 六个宽度 × 两个页面，
   `scrollWidth <= clientWidth`（无横向溢出），关键元素不出视口。
2. **对比度**：脚本从 CSS 变量算 WCAG 比值，正文 ≥ 4.5、大字 ≥ 3.0。
3. **交互**：`verify/e2e.cjs` 20 项既有契约全部保持通过（选择器契约见 §10）。
4. **视觉**：截图人工过目——探针只能证明「跑得对」，不能证明「看起来对」。
5. **无外部请求**：客人页零外部请求；主机页只允许 `youtube.com/iframe_api`。

## 10. 选择器契约（重构时必须保留）

既有 `verify/e2e.cjs` 依赖这些选择器，改版后逐条保留：

`#me` `.row` `.add` `#results` `#msg` `ol.q` `.playing` `#stage`
`#banner.show` `#queue li .qt` `#queue li .no` `#queue .del` `#count`
`#stats` `#nowTitle` `#nowBy` `#btnNext` `#btnSkip` `#btnMute` `#btnClear`

文案契约：`#me` 必须包含「还能点」或「名额」；配额用尽时切换为「名额用完」。
